# 模型重复加载：原因与可选方案

日期：2026-10-28。本文件是分析方案；同日已按建议实施课堂“暂停 / 继续”（模型归属同一次会话线程，暂停仅停止采集并处理尾句，继续时复用已加载模型与本课字幕归档），“结束并释放”保留原停止语义。限时保留、空闲常驻、GPU 权重暂存 RAM、启动预加载等选项仍未实施。

## 当前为什么每次开始都加载

当前模型属于一次会话的 `SessionWorker`，不属于应用生命周期：

1. `app.py` 的 `Controller.start()` 每次创建新的 `SessionWorker`。
2. `engine.py` 的 `run()` 创建 `LocalRecognizer` 和 `LocalTranslator`，加载两套权重，并在 CUDA 模式执行预热，然后才打开音频设备。
3. 停止时先排空已采集的语音，`finally` 对采集和模型调用 `stop()` / `close()`。
4. `recognition.py` 的 `close()` 清除 Whisper 引用；`translation.py` 的 `close()` 清除 CT2、分词器、简体转换器与句子缓存。`Controller.finished()` 再删除工作线程。

因此重新开始会重建模型和推理运行状态。Windows 可能已经缓存了文件页，第二次磁盘读取不一定与第一次一样慢，但文件缓存不能替代已经加载的模型、GPU 权重和预热状态。

现有验证记录的整次桌面测试约 30.8 秒，包含首次加载、预热、短音频输入和三段推理，不是独立测得的模型加载时长，也不能据此承诺复用后能省下多少秒。具体复用收益需要实施后用同一进程的首次启动、再次启动和资源占用对照测量。见 [桌面验证数据](validation-desktop.json)。

## 可选方案与代价

| 方案 | 适用场景与收益 | 内存 / 显存及行为取舍 |
| --- | --- | --- |
| 保持当前“停止即释放” | 课间长时间不用同传，资源及时让给浏览器等程序 | 下次需重新加载；仍是资源占用最低的空闲模式 |
| 增加“暂停 / 继续” | 同一堂课暂停视频、休息后接着听；只停采集、处理尾句，保留模型和同一课的字幕归档 | 模型在暂停期间继续占用 RAM / VRAM；暂停时不缓存后续声音。若音源没有同时暂停，该段内容会缺失 |
| 停止后保留模型 5 分钟 | 频繁停止、调整音频来源，再开一堂新的字幕会话；模型组合相同则复用，减少重载 | 空闲 5 分钟内继续占用资源；超时、手动释放、关闭应用或仅空闲时检测到资源紧张才释放。超过期限仍需重载 |
| 模型一直常驻到退出 | 希望窗口开着就随时快速开始 | 空闲占用持续到退出，不适合当前可用 RAM 偏低时作为默认 |
| 停止后把 GPU 权重暂存到 RAM | 显存紧张、系统内存充足时，在恢复速度与显存间折中 | 会增加系统内存压力；恢复还需 CPU → GPU 传输，可能仍需首段预热。对 16 GB RAM 且此前只剩约 1 GB 可用的状态，不建议默认启用 |
| 打开软件立即预加载 | 可在上课前打开软件等待加载，然后直接开始 | 将等待移到启动阶段；首次加载开销仍存在，空闲时也占用资源。不能单独解决每次停止后销毁模型的问题 |

“暂停”建议延续同一课程字幕与归档，排除暂停期间的音频时间；“结束”继续表示完成尾句并结束课程。新开课程仍应清空界面会话并新建归档。两者应有明确按钮与状态，避免用户把暂停误当作已经释放资源。

## CTranslate2 已有能力与限制

本地安装的 CTranslate2 **4.8.4** 已通过 Python 方法文档检查，无需加载模型即可确认：Whisper 和 Translator 都提供 `unload_model(to_cpu=False)` 与 `load_model(keep_cache=False)`。`to_cpu=True` 是暂存 CPU 内存，并非改用 CPU 识别；重新加载仍回到最初设备。`keep_cache=True` 会在恢复到 GPU 后继续保留 CPU 缓存，额外消耗 RAM。依据：[Whisper API](https://opennmt.net/CTranslate2/python/ctranslate2.models.Whisper.html)、[Translator API](https://opennmt.net/CTranslate2/python/ctranslate2.Translator.html)。

现有 `LocalRecognizer` 与 `LocalTranslator` 的 `close()` 并未调用这些暂存接口，而是丢弃整个对象引用。若改为暂存，需要保留其运行实例，并在没有推理请求时执行卸载；Translator 官方明确指出并发翻译时不保证卸载成功。依据：[内存管理](https://opennmt.net/CTranslate2/memory.html)、[Translator 卸载说明](https://opennmt.net/CTranslate2/python/ctranslate2.Translator.html#ctranslate2.Translator.unload_model)。

模型对象释放后，GPU 驱动上下文和 CTranslate2 的分配器缓存可能仍有占用，因此不能将“释放模型”等同于任务管理器中的显存立即变成 0。CTranslate2 使用 CUDA 缓存分配器 / 内存池以复用缓冲；本项目不依赖 PyTorch，调用 `torch.cuda.empty_cache()` 不是适用方案。本轮不会为这一分析更改分配器环境变量。依据：[CTranslate2 分配器说明](https://opennmt.net/CTranslate2/environment_variables.html#ct2-cuda-allocator)。

此前记录到聆听时整卡显存约 1,039 MiB，是一份短样例中的整卡观察值，不是模型精确独占占用，也不是峰值。本轮只读取已有记录，没有另行加载模型来推算常驻成本。CPU 权重文件大小也不能直接当作进程常驻内存。

## 针对本机的建议

优先采用**课堂暂停 / 继续**，同时保留**结束并释放**：90 分钟课程中，模型本来就会持续驻留；暂停继续可以避免课中反复加载，而下课后仍能明确释放资源。如果还希望不同课程之间快速重新开始，再提供可选的 **5 分钟模型保留**与“立即释放”，不建议默认无限常驻，也不建议默认把显存权重转移到仅有余量的 RAM。

若将来实施，模型应归属一个长期存在的串行推理线程，音频会话可以多次启停。复用需要验证模型路径、识别设备和翻译线程设置；更换语言不需要重新加载相同权重。切换识别模型 / 设备或翻译线程时，先安全释放旧实例再加载新实例，避免两套模型短暂重叠。出现 CUDA、模型加载或推理错误时应丢弃受影响实例，下一次重新加载；音频端点短暂故障不必自动销毁健康模型。

自动释放只能发生在暂停 / 已停止且无推理任务时，不能在课堂进行中为了瞬时内存警告卸载模型。5 分钟、资源余量阈值及恢复耗时都应作为可测、可调整的产品策略，而非库保证。
