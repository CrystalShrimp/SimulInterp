# 90 分钟课程：持续运行审查

本次增加的是流式边界回归测试，没有把加速测试描述为真实设备与模型连续运行 90 分钟。

`tests/test_long_session.py` 向真实 `SpeechSegmenter` 分批送入 90 分钟、16 kHz 的合成连续讲话信号，共 86,400,000 个采样点。测试复用一个 5 秒输入块，逐段消费输出，只保留字幕文本。它检查：

- 三档分别测试：智能 / 连贯档各完整 675 段、每段不超过 8 秒；低延迟档完整 1,080 段、每段不超过 5 秒。采样数连续且没有累计偏移。
- 分段活动帧、预卷帧、尚未处理的输入均保持固定上限。
- 最后一段的结束时间为 `01:30:00,000`，跨小时 SRT / TXT 时间戳正确。
- 三档字幕均可全部导出，而不是只导出界面中最近的 200 条。

这覆盖长流的内存边界、时间轴与导出，不覆盖 NVIDIA 驱动、声卡、温控、睡眠或真实课程语言的 90 分钟可靠性。真实长课验证仍需以至少 90 分钟连续采集和推理运行完成为准；长课期间应关注资源监测和累计跳过计数。

## 当前持续增长项与固定边界

| 部位 | 当前行为 | 与时长的关系 |
| --- | --- | --- |
| 原始采集队列 | 250 × 20 ms；满时保留较新的音频并记录跳过 | 固定约 5 秒；48 kHz 双声道 16 位 PCM 约 960 KB |
| 重采样 | 处理短块，保留有限的滤波上下文 | 固定；不保留整课原音频 |
| 语音分段 | 智能 / 连贯档最长 8 秒，低延迟档 5 秒；预卷约 200 ms；智能档只增加自然停顿阈值，不缓存额外历史 | 固定 |
| 推理队列 | 最多 3 段，连贯档最多约 24 秒、低延迟档约 15 秒 | 固定；持续处理不及实时会丢弃旧段，需要留意累计计数 |
| 识别/翻译模型 | 每次会话加载一次，结束释放引用 | 不随段数重复创建模型 |
| 翻译缓存 | 最近 128 条 | 固定 |
| 界面字幕记录 | 最近 200 条 | 固定；限制富文本重绘与界面内存 |
| 整课导出记录 | Controller 保留原文、译文与时间戳 | 随字幕条数增长，仅文本，不保留音频；不会截断在 200 条 |
| 自动字幕归档 | 每条中文字幕追加到独立 SRT 并刷新 | 文件随文本增长；不会把已有文件重新载入内存 |
| 性能监测 | 每 2 秒一份当前资源快照；无历史数组 | 固定；另经 2,701 次模拟采样检查 |

没有发现按课程时长累计原始音频、模型实例或无限推理任务的路径。字幕列表随时长增长是保留整课导出的必要行为；合成测试的整课字幕文件低于 256 KiB，真实课程取决于说话速度和文本长度。此文件大小不代表整个 Python / 模型进程的内存占用。

课程字幕会逐条写入 `exports/sessions/`。进程异常退出时，可直接读取已经写入的 SRT；未完成推理的语音不会恢复，自动保存也不是断电或磁盘故障的保证。写入失败会保留当前字幕文本供手动导出。运行中清空界面不会删除课程归档。

## 性能优化选择（2026-10-28 更新）

用户已选择 1、2、5；未选择 3、4。当前已移除自动语言检测，首次在设置中明确选择德语或英语并保存；翻译 beam 为 1；翻译线程经本机对照后默认 8，设置提供 4 / 6 / 8。识别仍使用 Turbo + beam 3。本节保留原始选项及其取舍作为设计记录，以下“原来”指本轮修改前。

1. **课程语言固定时指定德语或英语（已采用）。** 原来自动模式对每个语音段以 `language=None` 调用 faster-whisper；现在始终传入设置中的 de / en，跳过该检测分支。混合语言内容需手动切换课程语言。减少的是检测工作，不应承诺显著降低模型常驻显存。依据：[faster-whisper v1.2.1 实现](https://github.com/SYSTRAN/faster-whisper/blob/v1.2.1/faster_whisper/transcribe.py)。
2. **翻译 beam 从 2 改为 1（已采用）。** 同时显式关闭不需要的候选分数。官方明确列为提速方式，可能降低句子的译文质量。依据：[CTranslate2 性能指南](https://opennmt.net/CTranslate2/performance.html)。
3. **识别 beam 从 3 改为 1。** 减少解码候选是可测的提速选项，需要比较专业术语和口音识别；不能在没有本机测试时承诺省多少时间或显存。依据：[faster-whisper 解码参数](https://github.com/SYSTRAN/faster-whisper/blob/v1.2.1/faster_whisper/transcribe.py)。
4. **Small 作为显存紧张时的备用模型。** 参数量从 Turbo 的 809M 减为 244M，常驻权重更少；专业内容识别质量需要复测。不要默认它一定更快：OpenAI 的 A100 英文参考速度中，Turbo 比 Small 更快。官方原始 Whisper 的显存数字不应直接当成本项目 CTranslate2 INT8 的本机占用。依据：[Whisper 模型表](https://github.com/openai/whisper#available-models-and-languages)。
5. **翻译 CPU 线程作 4 / 6 / 8 对照（已采用）。** 原来使用 6 线程；本机正常短样本中 8 线程比 6 线程中值耗时少约 12.4%，CPU 占用更高，因此默认 8，仍可选 6 / 4。异常停顿样本单独保留、排除；详见 [实测报告](validation-cpu-tuning.md)。13900HX 是混合核心，这不等于 90 分钟功耗 / 温控最优。官方建议总线程数不要超过物理核心数。依据：[CTranslate2 性能指南](https://opennmt.net/CTranslate2/performance.html)。

已有的 GPU `int8_float16` 识别、CPU `int8` 翻译和单段推理继续保留。量化本身用于减少模型资源。依据：[CTranslate2 量化说明](https://opennmt.net/CTranslate2/quantization.html)。

对这台 8 GB 显存的机器，不建议为了离线文件吞吐量增加实时推理批量：上游基准显示批量增加也会增加显存占用，实时课程还会等候凑批。依据：[faster-whisper 官方基准](https://github.com/SYSTRAN/faster-whisper#benchmark)；上游硬件和模型与本机不同，数字仅用于说明取舍。
