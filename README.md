# 本地同传 · Deutsch / English → 中文字幕

Windows 原生桌面项目，面向 **i9-13900HX / RTX 4070 Laptop 8GB / 16GB 内存**。输入德语或英语语音，默认输出简体中文字幕，也可仅显示原文；支持电脑播放声音、麦克风、置顶悬浮字幕和 SRT / TXT 导出。

本机已准备默认模型并完成 GPU 推理和桌面验证，详见 [验证记录](docs/validation.md)。

## 开始使用

1. 安装 **Python 3.12 x64**（支持 3.10–3.13），确认 `python --version` 可用。现有 Anaconda 的 Python 3.12 也可以。
2. 双击 `setup.cmd`。它在当前目录创建 `.venv`，安装应用和 CUDA 运行库，下载识别模型和已量化的 INT8 翻译模型。首次需要联网和数 GB 下载，建议预留 **8GB 磁盘空间**；速度取决于网络。默认无需安装 PyTorch、完整 CUDA Toolkit、Ollama 或额外服务。
3. 双击 `start.cmd`。在界面选择：
   - **电脑播放声音**：选择标有系统声音 / loopback 的设备，与你播放视频、会议的输出设备保持一致。
   - **麦克风（默认）**：优先选择 Windows 默认输入麦克风；没有麦克风时才回退到系统回环。现场课可直接检查当前麦克风与权限。手动改选设备后，刷新时会保留仍可用的选择；设备编号不跨启动保存。
   - 点击右上角 **设置**：源语言、识别模型、计算设备、翻译 CPU 线程、本地模型下载、历史课程文件清理均在此处。课程开始后仍可查看，先结束并释放再修改。
   - **源语言必须预先指定德语或英语，不进行自动检测。** 首次打开会显示设置窗口，选择后记住；切换课程语言时请先修改设置。
   - **翻译为中文字幕**：默认开启。关闭后仅显示德语 / 英语原文，跳过翻译模型导入、加载和推理；识别完成即显示原文主字幕，悬浮字幕及 SRT / TXT 导出同样可用，不重复显示同一句。仍需等断句与识别，并非逐字零延迟。修改前先结束并释放；设置会保存。
   - **字幕节奏**：默认“清晰收音（实时优先）”，按本次清晰课堂素材优化：保留约 4.5 秒上下文后，遇约 0.3 秒自然停顿即可提前处理；短句仍等约 0.8 秒停顿，连续讲话最长 8 秒。上下文包含预卷和句中停顿，不代表连续 4.5 秒有声语音。“较差收音（长上下文）”先保留原固定 0.8 秒 / 8 秒，后续单独优化；另保留“低延迟”0.5 秒 / 5 秒。按环境手动选择，各档都需加识别和翻译耗时；更早断句可能改变个别句子的识别，先结束并释放再切换。
   - 模型：默认 **Large v3 Turbo**，运行设备 **GPU / CUDA**。
   - 中文翻译默认 **8 个 CPU 线程、1 个候选**；可在设置中选择 4 / 6 / 8 线程。识别仍使用 3 个候选，不因性能监测自动更换模型。
4. 点击“开始同传”，**等待状态变为“正在聆听”后**再播放音视频或说话。开始时会先加载模型并预热 GPU，本机测试需要约 20–30 秒；此时尚未采集声音。点击“悬浮字幕”可让字幕显示在其他普通窗口上方，支持拖动和调节字号。
5. 课中可**暂停 / 继续**：暂停会停止采集并处理已录入的尾句，识别与翻译模型保持加载，字幕记录与 SRT 归档延续，继续时无需重新加载模型；暂停期间模型仍占用内存与显存，本次时长不含暂停时间。**结束并释放**才会卸载模型、让出资源；暂停中也可以直接结束。
6. 结束后可手动导出 SRT 或 TXT。**每次开始新的同传会清空上次会话的界面记录。** 已完成的中文字幕会逐条自动保存为 `exports/sessions/日期-时间-标识.srt`，无需等下课；界面显示保存状态，鼠标悬停可查看完整路径。界面只显示最近 200 条，手动导出包含本次未清空的全部字幕。课中“清空”不删除自动归档文件；归档可在设置的“清理课程文件”中按次勾选删除或全选删除（删除前有确认，不可恢复，课程进行中不可清理）。
7. 程序以无控制台方式运行，不会在任务栏残留命令行窗口。点击“收起到托盘”、最小化或关闭按钮可收起主窗口；同传继续运行，课程进行中会自动打开独立置顶字幕，后台持续更新，也不会抢走其他应用的焦点。双击托盘图标恢复主窗口；托盘右键的“悬浮字幕”可单独开关字幕，也可暂停、结束或退出。手动关掉字幕后不会被下一条字幕强制弹出；真正退出时字幕一并关闭。极早期的启动异常会写入 `logs/app.stderr.log`。

模型准备完成后，识别和翻译均从本机文件加载；运行阶段强制 Hugging Face / Transformers 离线模式，不调用任何云端识别或翻译接口。正常同传的音频仅在内存中处理；只有手动开启下述“诊断采样”才额外保存音频。点击“下载 / 准备模型”会显式开启联网准备子进程。

## 采集识别诊断素材

1. 开始同传，等待“正在聆听”。
2. 打开 **设置 → 诊断采样 → 录制 5 分钟诊断素材**，现场课正常收音即可；视频课再播放要比较的片段。排查速度时保持当前模型、断句与线程设置，尽量包含连续讲解和自然停顿。没有点击此按钮时不会保存录音，也不回溯此前声音。
3. 主面板底部显示红色采样进度；最多保存 300 秒音频，也会在开启满 5 分钟时自动收尾，空闲设备不会无限等待。可以提前点击“结束本次采样”；暂停或结束课程同样会收尾。停止诊断采样不结束同传。
4. 状态中可复制保存目录，位于 `diagnostics/日期时间-标识/`。保留整份目录：`audio.wav` 是进入语音过滤前的 16kHz 单声道 PCM16 识别输入（不是声卡原生 48kHz 音轨）；`transcripts.jsonl` 保存当时已完成的识别原文、片段时间与耗时；`latency.jsonl` 保存对应片段的断句末尾等待、排队、识别和翻译等软件耗时；`metadata.json` 保存模型、语言、断句与采样起点；`report.json` 记录完整性和结束原因。课程时间减去 metadata 的 `course_start_seconds` 即为诊断 WAV 的大致时间位置。

开启翻译时，英文原文与中文字幕在翻译完成后一起显示，因此两者一起晚出现并不能单独判断识别慢。关闭翻译则在识别完成后发出原文，耗时记录明确标记 translate_enabled=false，面板翻译耗时显示“关闭”。新耗时记录不包含声卡、采集队列与界面绘制延迟，也不是麦克风到屏幕的完整延迟。停止采样后不继续收集尾段事件，最后仍在处理的耗时可能缺失。

自动到时可能早于最后几个片段推理结束，JSONL 因此可能没有末尾尚在推理的文字；WAV 仍可用于离线复测。采样起点可能位于一个正在断句的片段中，首个识别事件可以包含起点前的上下文，其诊断相对时间为负值，比较时应跳过这部分。文件只保存在本机，不自动上传；5 分钟 WAV 约 9.6 MB。写盘与录音队列有界，故障会明确标记该份诊断不完整，不为录音额外加载识别模型或改变同传参数。

## 处理方式与硬件分配

```text
Windows WASAPI 电脑声音 / 麦克风
    → 单声道 16 kHz 重采样
    → WebRTC 语音检测：默认智能自然停顿断句，保留上下文、最长约 8 秒
    → Faster Whisper large-v3-turbo（CUDA INT8 + FP16）
    → 德文 / 英文原文
    → M2M100 418M（CPU INT8，8 线程 / beam 1，直接译中文）
    → 简体中文转换 → 主界面 / 悬浮字幕 / SRT
```

识别模型主要使用显存；开启翻译时，翻译模型使用 CPU 和内存，避免两套模型竞争 8GB 显存。仅原文模式不要求翻译模型文件，设置中的模型准备也只准备所选识别模型。不预先承诺具体显存峰值或翻译速度；占用与设备、模型、驱动、音频和其他程序有关。

这是**分段实时字幕**：字幕会在一段语音结束或达到切段长度后出现，还要加上识别和翻译耗时。它不是逐字零延迟同传。德语长句、专有名词、背景音乐、口音或切段处都可能影响准确率；M2M100 是轻量翻译模型，不具备大型云模型的语境能力。

待处理语音队列最多 3 段。持续积压时会明确提示并跳过最旧片段，让字幕继续跟上当前内容；导出时间戳保留缺口。可切换 Small 或关闭其他负载改善。停止时会完成已采集的尾句及队列，等待当前推理安全结束。

## 性能监测与 90 分钟课程

主面板每 2 秒更新，监测不会额外加载模型或创建 CUDA 上下文：

| 指标 | 如何判断 |
| --- | --- |
| CPU / GPU 利用率 | 观察识别或翻译时的负载，短暂峰值本身不是故障 |
| 系统可用内存 / 总内存 | 可用量低于 1 GB 或 10% 时提醒；课前即可查看 |
| 本软件内存 | 当前进程物理内存工作集，便于观察是否持续增长 |
| 显存占用 / 总显存 | NVIDIA GPU 0 的整卡占用，包含其他程序；选择 GPU 识别时，余量不足 512 MB 会提醒 |
| GPU 温度 | 驱动支持时显示，便于观察长时间运行情况 |
| 本次时长 | 从实际开始聆听计时，暂停期间暂停计时；无 90 分钟截断，跨小时显示 |
| 待处理段数 / 秒数 | 持续增加表示字幕在落后；原始音频和语音队列均有容量上限 |
| 处理速度 RTF | 最近完成一段的“识别 + 翻译耗时 / 音频时长”，小于 1 表示处理快于实时；不包含等待断句的时间。连续 3 次监测偏慢且有积压会提醒 |
| 识别 / 翻译 | 最近一段两个阶段各自耗时；“待处理”的悬停提示另显示最近一段音频长度与排队时间，避免将 RTF 小于 1 当成字幕没有延迟 |
| 采集 / 跳过 | 分别显示设备溢出次数与识别积压跳段数；悬停查看采集队列跳过的已知秒数 |
| 字幕归档 | 逐条写入并刷新到本地 SRT，写入失败会明确提示，仍可手动导出 |

读不到的监测项显示“暂不可用”，不会用 0 冒充。资源提示用于提前发现压力，不保证驱动或推理库永远不会异常；不会在课堂中自动切换模型或打断会话。

长课只累计字幕文本，不累计整课原始音频。音频队列约 5 秒、推理队列 3 段、分段器最长 8 秒（低延迟档 5 秒）、翻译缓存 128 条、界面最近 200 条均有固定上限。自动 SRT 在进程异常退出后仍可读取已经写入的字幕，但不包含尚在推理的语音，也不能保证断电或磁盘故障时的数据完整性。

已经通过 **90 分钟加速流式回归**：三种节奏分别让真实分段器处理 86,400,000 个采样，智能 / 连贯档各导出 675 段、低延迟档导出 1,080 段连续讲话字幕，时间轴均到 `01:30:00`，并检查内部缓冲上限。尚未完成真实声卡、真实课程和模型连续 90 分钟的硬件实跑；详见 [长课审查与已选择的优化](docs/long-session-review.md)。

## 已采用的性能设置

已按用户选择启用：显式课程语言、翻译 beam 2 → 1、翻译 CPU 4 / 6 / 8 线程对照。识别仍为 Turbo + beam 3，没有因本次优化切换 Small。

6 条德英课堂文本的正常短样本实测，6 线程两轮中值约 2.288 秒，8 线程约 2.004 秒（约减少 12.4%），代价是翻译期间进程占整机 CPU 从约 18.5% 提升到约 24.3%。因此新设置默认 8 线程；更看重低 CPU 占用时可以改为 6 或 4。线程变化不会改变解码参数；本批样本各线程译文一致，但这不是全量翻译质量保证。

测试期间内存余量偏低，一组 4 线程出现约 642 秒异常停顿，不能用作线程速度排名，也不能仅凭它断定根因。报告保留原始记录并明确排除该组。工具增加可用内存检查，避免余量不足时继续对照；本轮没有运行额外 GPU 识别模型。完整数据与限制见 [线程实测](docs/validation-cpu-tuning.md)。

已实施课堂**暂停 / 继续**：暂停只停止采集并处理尾句，识别与翻译模型保持加载，字幕记录与 SRT 归档延续；“结束并释放”沿用原停止语义，排空尾句后卸载模型、让出内存与显存。暂停期间模型仍占用资源，且暂停时不缓存后续声音。其余方案（停止后限时保留、空闲常驻、GPU 权重暂存 RAM）未实施；分析见 [模型重复加载与取舍](docs/model-lifecycle-options.md)。

## 其他启动方式

```powershell
# 安装但暂不下载模型
.\setup.ps1 -SkipModels

# 只用 CPU（速度较慢，界面中需选 CPU）
.\setup.ps1 -CpuOnly -Model small

# 下载/续传默认 Turbo 模型与共用翻译模型
.\.venv\Scripts\python.exe -m simulinterp.prepare_models

# 另行准备 Small 模型
.\.venv\Scripts\python.exe -m simulinterp.prepare_models --asr small

# 只检查本地文件，不联网
.\.venv\Scripts\python.exe -m simulinterp.prepare_models --check

# 可选：自行从 Meta 官方原始权重转换（下载更大，需要 CPU PyTorch）
.\.venv\Scripts\python.exe -m pip install torch==2.6.0 --index-url https://download.pytorch.org/whl/cpu
.\.venv\Scripts\python.exe -m simulinterp.prepare_models --convert-official

# 检查运行库与设备；不会打开录音流
.\.venv\Scripts\python.exe -m simulinterp.diagnose

# 可选：本机翻译线程对照（需要足够可用内存；不加载 GPU 识别）
.\.venv\Scripts\python.exe -m simulinterp.benchmark_translation --output cpu-tuning.json

# 翻译已有音频文件（也适用于 PyAV 能解码的视频）
.\.venv\Scripts\python.exe -m simulinterp.transcribe --audio sample.wav --language de --device cuda --output exports\sample.srt

# 仅生成原文字幕，不加载翻译模型
.\.venv\Scripts\python.exe -m simulinterp.transcribe --audio sample.wav --language en --no-translation --output exports\original.srt

# 仅下载 / 检查识别模型，用于原文字幕
.\.venv\Scripts\python.exe -m simulinterp.prepare_models --asr-only
.\.venv\Scripts\python.exe -m simulinterp.prepare_models --asr-only --check

# 可选：恢复原来的短断句节奏；默认 adaptive 智能断句，coherent 为原连贯模式
.\.venv\Scripts\python.exe -m simulinterp.transcribe --audio sample.wav --language en --asr-profile fast

# 单元测试：不下载模型，不采集声音
.\.venv\Scripts\python.exe -m pip install -e '.[dev]'
.\.venv\Scripts\python.exe -m pytest -q --basetemp=.pytest_tmp
```

默认所有模型与缓存都保存在项目目录：`models/`、`.cache/huggingface/`。环境变量 `SIMULINTERP_HOME` 可改为其他存储目录；准备模型和运行应用必须设置相同值。默认翻译模型来自固定版本的社区 CTranslate2 转换，约 500MB，下载后校验各文件的 SHA256；原始模型来自 Meta，许可为 MIT。选择 `--convert-official` 时，官方原始权重会保留在 `.cache`，方便复用及恢复。

语言、模型、计算设备、翻译开关、字幕节奏、翻译线程保存在同一数据目录的 `settings.json`，重启恢复；音频设备索引不跨启动保存，以免 Windows 重新枚举后选错设备。旧设置中没有字幕节奏时采用清晰收音模式，没有翻译开关时仍启用中文翻译；已经明确保存的模式会保留。文件转译命令也必须显式指定 `--language de` 或 `--language en`，可用 `--translation-threads 4|6|8` 覆盖翻译线程。

## 常见问题

- **双击 `start.cmd` 后没有窗口**：程序通过 `pythonw` 无控制台启动，窗口正常时会直接出现；若没有，请查看系统托盘，并检查 `logs/app.stderr.log` 是否记录了启动异常。
- **提示音频缓冲区溢出，但电脑并不繁忙**：已修复首次采集时加载重采样库造成的拥堵，以及把驱动短暂丢帧当成致命错误的问题。请关闭旧窗口后重新运行 `start.cmd` 使新代码生效。当前版本在打开音频流前完成初始化，短暂丢帧会自动继续采集并显示状态提示；内部队列丢帧会保留相应的时间缺口。
- **模型尚未就绪**：先运行 `setup.cmd`；下载中断后重新执行即可续传。仅有模型目录不表示完整，应用会检查所需文件，实际加载失败会显示错误。
- **CUDA / cuDNN / cuBLAS 加载失败**：重新执行 `setup.cmd`，确认安装 `[cuda]` 依赖且使用 `.venv` Python。程序自动注册该环境内 NVIDIA DLL 路径。NVIDIA 驱动需支持 CUDA 12；`nvidia-smi` 中的 CUDA 版本只代表驱动能力。若仍失败，先使用 Small + CPU。
- **显存不足**：关闭游戏、其他 AI 程序或高显存应用，再切换 Small。默认不会偷偷切换 CPU。
- **没有字幕**：看音量条；选择正确的 loopback 输出端点，刷新设备后再开始。更换耳机、HDMI、蓝牙输出后通常需要重新选择。独占音频、受保护媒体或特殊声卡可能无法由 WASAPI 捕获。
- **蓝牙声音变差**：蓝牙耳机麦克风可能触发通话模式。电脑声音翻译时使用 loopback，不必同时启用耳机麦克风。
- **窗口无法盖住独占全屏游戏/视频**：切换无边框窗口或普通全屏。悬浮字幕默认置顶于普通桌面窗口，不能保证覆盖所有独占全屏程序。
- **下载连接失败**：检查终端中的代理、证书和网络设置；应用不擅自更改系统代理。可以通过 Hugging Face Hub 支持的环境变量配置自己的访问端点，然后重新准备模型。

## 上游与许可

- [Faster Whisper](https://github.com/SYSTRAN/faster-whisper)：本地多语言语音识别。其 GPU 运行依赖 CUDA 12 cuBLAS 与 cuDNN 9。
- [Whisper Large v3 Turbo 的 CTranslate2 转换](https://huggingface.co/dropbox-dash/faster-whisper-large-v3-turbo)：MIT 模型；默认按此仓库下载，首次约 1.6GB。
- [M2M100 418M 官方模型](https://huggingface.co/facebook/m2m100_418M)：MIT 模型，直接支持德语、英语和中文。
- [M2M100 418M INT8 转换](https://huggingface.co/jncraton/m2m100_418M-ct2-int8/tree/7c1b2620a4e58dacecbd8bf89cfd6da7eb9eb7b0)：默认翻译权重，固定版本并校验 SHA256。
- [CTranslate2 官方转换及推理文档](https://opennmt.net/CTranslate2/guides/transformers.html)：M2M100 INT8 CPU 推理。
- PySide6 / Qt 使用 LGPL 等上游许可；分发程序时需遵守其许可要求。本项目源码采用 MIT（见 `LICENSE`），模型及依赖各自许可仍适用。
